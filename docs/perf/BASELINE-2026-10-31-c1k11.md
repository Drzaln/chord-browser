# c1k.11 — hidden pages, 2026-10-31 (early morning)

Release build, the tab set in Spaces 3 and 4, both YouTube videos confirmed
paused in WebKit's log (`pauseInternal`), Chord hidden (Cmd-H). Per-process
CPU from `ps` cputime over 120 s, after settling (3 min before, 5 min after).

| | before | after `hiddenPageDOMTimerThrottlingAutoIncreases` |
|---|---:|---:|
| YouTube page processes | 16.3 + 9.8 ms/s | 9.2 ms/s |
| All Chord processes | ≈48 ms/s | ≈26 ms/s |

Safari turns this WebKit preference on: a page's timers are spread further
apart the longer it stays hidden. WebKit leaves it off for apps. The
comparison is not perfectly controlled (a relaunch in between; the second
YouTube tab may share the first one's process after it), so the next
powermetrics run of the tab set is the real number.

Also found on the way: a playing video costs the GPU process ~43 ms/s
hidden (a live CoreAudio output loop plus sample enqueueing), and the
tab-set script's YouTube tab autoplays, so a "paused" run has to check the
log, not the screen.
